## Tested sources
### ctx.tool.web_search — the consortium feed
**Used by**: `refreshIdeas` (daily refresh + manual generate). Runs a rotating battery of queries each run: pharma shortages / CDMO capacity, underserved SaaS niches, weird-but-profitable consumer niches, AI services market, online/AI art market, self-hosted/homelab economy, grant and funding programs.
**Test command**: `bun /opt/muse/assets/spaces/ts-runtime/dist/probe-ctx.js < /tmp/probe4.ts` and `< /tmp/probe6.ts` — snippet calls `ctx.tool.web_search("<query>", { language_code: "en" })` (note: first positional arg is the query string, not an object — verified from the runtime source after two failed object-shaped attempts).
**Sample output**: Query `emerging weird business opportunities 2026` returned vettedthis.com (subscription box market $32B in 2026 growing 14%/yr; US pet industry $158B in 2025) and preuve.ai/BigIdeasDB (2,463 revenue-verified startups; freight-logistics and small-practice healthcare market-gap scores 9.0/10). Query `drug shortage pharmaceutical supply chain market size` returned CDMO market $210–260B in 2025 projected $330–375B by 2031, GLP-1 $53B (2025) → $157B (2030), compounding pharmacy $15.48B (2026) → $21.01B (2031) at 6.3% CAGR with verbatim source URLs. Query `art market fractional ownership AI art market size` returned Mordor Intelligence online fine art $14.1B (2026) → $18.99B (2031) at 6.13% CAGR and AI-in-art $5.32B (2025) → $40.4B (2033) at 28.84% CAGR. Result shape: `{ content: { summary, results: [{ title, url, source, snippet, rank }], sources: [{ title, url }] } }`.
**Processing**: Search results are passed verbatim (title, snippet, URL) into the synthesis prompt as the only allowed evidence pool. The model must attach evidence items to ideas using only URLs present in that pool; the server drops any evidence item whose URL is not in the pool before saving. Market size / growth strings shown on cards come from those evidence items, never from model memory alone.

### ctx.inference.complete — idea synthesis
**Used by**: `refreshIdeas` — synthesizes 6 new ideas per run from the search evidence pool + the user's active lenses, and scores each for craziness.
**Test command**: `bun /opt/muse/assets/spaces/ts-runtime/dist/probe-ctx.js < /tmp/probe6.ts` — snippet calls `ctx.inference.complete(prompt, { schema: z.object({...}) })` (schema is required; the probe harness passes `z` as the snippet's second argument).
**Sample output**: For a pharma supply-chain expert / artist / AI orchestrator prompt it returned `{ title: "Cold Chain Canvas: Where Life-Saving Drugs Become Living Art", hook: "An AI orchestrator turns live pharma cold-chain data into generative art…", crazyScore: 9.4 }` — confirming the model produces genuinely cross-domain, personalized, high-weirdness ideas from his actual profile.
**Processing**: One structured call per refresh returns an array of ideas with fields: title, hook, type (business | art | hybrid), crazyScore (1–10), whyShyAway, marketSignal, upsideCase, whyForYou, firstMove, sevenDayTest, evidence[] (label, value, sourceUrl). Server validates with Zod, filters evidence URLs against the search pool, then inserts as a new dated batch. Saved / pursuing ideas from earlier batches are never touched by a refresh.

## Long-term data behavior
- **Refresh policy**: Daily cron (installed from the build's refresh triggers) calls `refreshIdeas`, which appends one new batch of ideas inline. The in-page "Run a fresh sweep" button (optionally focused on one lens) uses a job pattern instead, because the search + synthesis chain outlives a single action call — the original synchronous button path timed out silently and left no trace (user report 2026-11-06: "I pressed run a fresh sweep and nothing occurred"; live board confirmed unchanged). `startSweep` writes a `sweep_jobs` row and spawns a background task (`ctx.agent.spawnTask`, `expectsAction: "completeSweepJob"`) that runs the same searches, reports stage progress via `updateSweepStage` (searching → synthesizing → saving), and delivers pool + ideas to `completeSweepJob`, which runs the identical pool-URL validation and save. The board polls `getSweepStatus` every 4s; that action also reconciles a dead/stalled worker (agent status failed / contract unsatisfied / no progress for 10 min) into a persisted failure naming the stage it stopped at, shown with a retry button. `refreshIdeas` remains for the daily cron.
- **Growth**: Ideas accumulate by batch; the board defaults to the newest batch plus everything the user saved or marked pursuing. Dismissed ideas are archived (status flag), not deleted, so refresh dedupes against prior titles.
- **Ordering**: Newest batch first; within a batch, highest crazy score first. Saved vault sorts by status then recency.
- **Time semantics**: `created_at` / batch timestamps are server instants rendered viewer-local (America/New_York). Market figures keep the year printed in their source snippet (e.g. "2026", "by 2031") rather than a converted date.

## Imagery
Imagery not needed: the subjects are abstract business/art concepts with no real-world referent to photograph, and generated stand-ins would misrepresent them. Visual identity comes from typography, the crazy-meter, and market-data chips; every card's credibility object is its linked source evidence, not a picture.

## Rejected approaches
- **Tried**: Calling `ctx.tool.web_search` with an object argument (`{ primary_query: {...} }` and `{ query: "..." }`).
  **Why rejected**: Both failed with `query.trim is not a function` — the runtime signature is `web_search(queryString, options)`, confirmed by reading the runtime source and a successful probe.
- **Tried**: `ctx.inference.complete({ messages })` without a schema.
  **Why rejected**: Runtime requires a Zod `schema` in options; the corrected `(prompt, { schema })` form probed successfully.
- **Considered**: A static, hand-written starter set of ideas baked into a migration.
  **Why rejected**: It would go stale immediately and its market numbers would be unverifiable model memory. The brief demands real-world data per idea, so all shipped ideas come from the live search → synthesis pipeline, including the first batch via post-submit refresh.
